## 1. 产品定位

Ask "Me" 是一个以“提问箱”为核心的轻量 Web 产品：箱主创建并分享自己的提问入口，访客提交问题或留言；系统将问题沉淀为可管理的数据，由 AI 为箱主准备可编辑的回复草稿，最终以箱主授权的方式回复或发布。

它不是泛化聊天机器人，也不应让 AI 冒充箱主。其价值在于将分散、重复、难以及时处理的问题，变成一套可收集、筛选、辅助回答、沉淀洞察的流程。

### 1.1 MVP 目标

- 让箱主能在几分钟内获得一个可分享的提问链接。
- 让提问者以低摩擦方式提交一条问题，并清楚知道其提交状态与隐私边界。
- 让箱主可以浏览、筛选和处理收件箱中的问题。
- 让 AI 将“起草”工作从箱主手中接过，但始终保留人工决定权。
- 让箱主能把已处理问题的回复，以明确的公开/私密方式交付给提问者。

### 1.2 非目标（MVP）

- 不构建开放式社交信息流、陌生人广场或复杂社区关系。
- 不把 AI 自动发送或自动公开作为默认行为。
- 不在没有确认合规与审核机制前，处理敏感个人信息、医疗/法律/金融结论或未成年人数据。

## 2. 用户角色与核心场景

| 角色 | 主要目标 | 关键权限 |
|---|---|---|
| 箱主 Owner | 创建提问箱、收集问题、审核并回复、查看洞察 | 完整管理自身提问箱与其数据 |
| 提问者 Asker | 向特定箱主提出问题，必要时匿名 | 仅可提交、查看自己可访问的结果 |
| 管理员 Admin（TBD） | 平台安全、举报处理、必要的内容处置 | 仅访问履行运营与安全职责所需的数据 |

### 2.1 核心场景

1. **分享收集**：创作者、顾问、社群主或个人将 `ask.me/{slug}` 放到个人主页、社交媒体或群聊中，访客进入后提交问题。
2. **批量处理**：箱主打开收件箱，先过滤垃圾和敏感问题，再让 AI 按其设定的语气准备回复草稿，修改后发送或发布。
3. **内容沉淀**：箱主从高频问题中识别主题和需求，形成 FAQ、选题或服务线索。MVP 可先提供基础标签和频次统计。
4. **匿名互动（TBD）**：若启用匿名模式，提问者可不展示身份；平台仍需保留反滥用所必需的最小技术记录与告知。

## 4. 关键用户流程

### 4.1 箱主首次使用

1. 登录或注册（认证方式 TBD）。
2. 填写显示名称、头像（可选）、短介绍和唯一 slug。
3. 系统创建默认提问箱；箱主可设置标题、说明、是否允许匿名与默认回复可见性（均为可配置项）。
4. 进入“分享”页复制链接。
5. 首次进入收件箱时展示引导和空状态。

### 4.2 提问者提交问题

1. 打开箱主分享链接。
2. 看到箱主身份、提问箱标题、简短说明、问题输入区和隐私提示。
3. 输入问题；客户端显示字符数、必填校验与提交按钮状态。
4. 提交前仅收集当前隐私策略允许的信息；如匿名关闭，必须明确说明将展示/收集什么身份信息。
5. 提交成功页给出简洁确认；若支持回复通知或查询码，须在此处清晰说明（TBD）。

### 4.3 箱主 AI 辅助回复

1. 箱主从收件箱选择一条待处理问题。
2. 先阅读原问题与已有上下文；可标记垃圾、敏感、需跟进或归档。
3. 点击“生成回复草稿”。系统将问题、箱主明确保存的回复风格和必要上下文送入 AI。
4. AI 返回草稿，并明确标记为“AI 草稿，发布前请核对”。
5. 箱主可编辑、重生成、复制或放弃。每次生成应可记录模型版本和时间，但不暴露密钥。
6. 箱主主动选择“保存草稿”“私密发送”或“公开发布”（后两项是否开放为 TBD），再二次确认。

### 4.4 状态机

`submitted`（已提交） -> `reviewing`（处理中） -> `drafted`（有草稿） -> `answered_private` 或 `published`（已回复） -> `archived`（归档）

补充分支：`spam`、`flagged`、`deleted`。删除最好采用软删除与保留期策略（TBD），使误操作与安全调查可控。

## 6. UI UX 与设计系统

### 6.1 设计方向

关键词：克制、温暖、私密、清晰、可控。产品应像一个精致的个人收件箱，而不是嘈杂社交平台或炫技式 AI 工具。

### 6.2 设计令牌建议（可根据现有 Logo 颜色调整）

- 字体：优先使用系统无衬线字体栈；中文优先 `PingFang SC` / `Microsoft YaHei`，保证跨端稳定。
- 字号：正文不小于 14px；移动端关键操作和输入文本建议 16px，避免浏览器自动缩放。
- 间距：4px 基础网格；页面水平留白移动端 16-20px、桌面端 32-48px。
- 圆角：卡片 12-16px，按钮 10-12px；避免过度胶囊化。
- 对比度：正文和按钮状态达到 WCAG AA；不单独依赖颜色传达状态。
- 色彩：从现有 Logo 中提取主色/中性色形成 token；在未审阅 Logo 前，不自行定义替代品牌主色。

### 6.3 组件

- Button：primary、secondary、ghost、destructive、loading、disabled。
- Input / Textarea：label、help text、error、字符计数、聚焦和禁用状态。
- Status badge：submitted、reviewing、drafted、answered、published、spam、flagged、archived。
- Question card、AI draft panel、empty state、toast、confirm dialog、filter chip、skeleton。
- 对破坏性操作（删除、标记垃圾、公开发布）使用二次确认；不可用颜色替代文字说明。

### 6.4 动效

- 使用 150-240ms 的轻量淡入、位移或高度过渡，服务于反馈，不做装饰性大幅运动。
- 提交、生成草稿和发布提供进行中状态、可感知的完成反馈和错误恢复入口。
- 尊重 `prefers-reduced-motion`：减少或关闭非必要动画。

### 6.5 响应式验收

- 覆盖至少 320px、375px、768px、1024px、1440px 宽度。
- 移动端：单列；底部/顶部操作栏不遮挡输入；触摸目标不小于约 44px。
- 平板：允许两栏，不强制桌面三栏。
- 桌面：收件箱信息密度可提高，但正文行宽保持可读。
- 不出现横向滚动、被遮挡的弹窗、不可点击的固定按钮或仅悬停可达的关键功能。

## 8. AI 能力与人工审核边界

### 8.1 AI 可做的事

- 根据单条问题生成回复草稿。
- 依据箱主明确配置的语气、长度、语言和可选资料生成草稿。
- 对问题做主题建议、风险提示、去重候选和摘要（P1 / TBD）。

### 8.2 AI 不得做的事

- 不自动以箱主身份发送、发布或承诺任何内容。
- 不捏造箱主经历、联系方式、价格、政策或事实。
- 不将一个箱主的私有问题、回答或资料泄露到另一个箱主的上下文。
- 不以“AI 建议”绕过垃圾、仇恨、骚扰、违法、未成年人或高度敏感内容的人工审核。

### 8.3 实施要求

- 所有 AI 输出均标识为草稿，并允许箱主查看、编辑、复制、删除和重生成。
- 发送给模型的数据最小化：默认只包含当前问题、经箱主授权的系统设定和必要上下文。
- 提示词从服务端组装，禁止在客户端暴露供应商密钥或系统提示。
- 设置超时、重试上限、内容安全检查和降级文案；模型失败时仍可人工回复。
- 对高风险内容给出“需人工核对”的界面提示，不输出武断结论。

## 9. 数据模型建议

以下为关系型数据库（PostgreSQL）示例，字段可随已选技术栈调整。

| 实体 | 核心字段 |
|---|---|
| `users` | `id`, `email`, `display_name`, `avatar_url`, `created_at`, `deleted_at` |
| `question_boxes` | `id`, `owner_id`, `slug`, `title`, `description`, `logo_override?`, `anonymous_mode`, `default_reply_visibility`, `status`, `created_at` |
| `questions` | `id`, `box_id`, `content`, `asker_display_name?`, `asker_contact?`, `is_anonymous`, `status`, `risk_level`, `submitted_at`, `deleted_at` |
| `answers` | `id`, `question_id`, `content`, `visibility`, `source` (`human`/`ai_assisted`), `published_at`, `sent_at` |
| `ai_generations` | `id`, `question_id`, `owner_id`, `provider`, `model`, `prompt_version`, `output`, `status`, `created_at` |
| `tags` / `question_tags` | 箱主或系统标签与关联 |
| `audit_logs` | `id`, `actor_id?`, `action`, `resource_type`, `resource_id`, `metadata_minimized`, `created_at` |
| `reports` | `id`, `reporter_id?`, `resource_type`, `resource_id`, `reason`, `status`, `created_at` |

**关键约束：** `slug` 唯一；所有箱主数据查询必须以 `owner_id` / 所属 `box_id` 做行级授权；提问者联系方式应独立加密或不收集，取决于待确认的回复方式。

## 10. API 与后端建议

### 10.1 API 设计（REST 示例）

- `POST /api/auth/*`：认证（按所选供应商实现）。
- `GET /api/boxes/{slug}`：获取公开提问页所需的最小公开资料。
- `POST /api/boxes/{slug}/questions`：提交问题；带验证码/限流/内容校验。
- `GET /api/me/boxes`、`POST /api/me/boxes`、`PATCH /api/me/boxes/{id}`：箱主管理。
- `GET /api/me/questions`：支持 `status`、`tag`、`q`、分页。
- `GET /api/me/questions/{id}`、`PATCH /api/me/questions/{id}`：详情和状态处理。
- `POST /api/me/questions/{id}/ai-drafts`：服务端请求模型，返回异步任务或草稿。
- `POST /api/me/questions/{id}/answers`、`PATCH /api/me/answers/{id}`、`POST /api/me/answers/{id}/publish`：保存、编辑、发布回复。
- `POST /api/reports`：举报。

### 10.2 架构原则

- 先检查现有仓库的框架、路由、认证、数据库、部署方式与代码规范，**不要因偏好直接重写技术栈**。
- 若仓库为空，可选用成熟全栈方案（例如 Next.js + TypeScript + PostgreSQL + ORM），但须将选择理由写入 README，并保持模块边界清晰。
- API 层做身份验证、资源所属校验、输入验证、速率限制和错误映射；不可仅依赖前端隐藏按钮。
- AI 调用放在后端服务或受保护的 server action 中；对耗时生成使用队列/异步任务是可选优化。
- 使用环境变量管理数据库、认证、AI 供应商、邮件和分析配置；提供 `.env.example`，绝不提交真实密钥。

## 11. 权限、隐私、安全与合规

### 11.1 权限矩阵

| 行为 | 提问者 | 箱主 | 管理员（TBD） |
|---|---:|---:|---:|
| 查看公开箱主页 | 是 | 是 | 是 |
| 提交问题 | 取决于箱设置 | 是 | 是 |
| 查看原始问题 | 仅自己的可访问记录（TBD） | 仅自己的箱子 | 按职责最小化 |
| 生成/编辑 AI 草稿 | 否 | 是 | 否/仅支持处理 |
| 发布回答 | 否 | 仅自己的箱子 | 受限 |
| 删除/导出数据 | 请求权利（TBD） | 仅自己的数据 | 合规处理 |

### 11.2 必做安全控制

- 对公开提交接口做 IP/设备级速率限制、验证码或隐形挑战（具体供应商 TBD），并防 CSRF、XSS、注入、枚举与滥用。
- 验证和规范化所有输入；前端渲染用户内容时转义 HTML。若支持富文本，使用严格白名单净化。
- 认证 cookie 使用 `HttpOnly`、`Secure`、适当 `SameSite`；密码由受信认证服务处理，不自行保存明文。
- 记录安全相关审计日志，日志中避免存原始敏感问题、邮箱、token 或 AI 密钥。
- 公开页不得暴露内部 ID、邮箱、IP、提问者联系信息、AI 系统提示或模型密钥。
- 提供可访问的隐私政策、使用条款、举报与删除请求入口；具体法律适用地和保存期限为 TBD，必须由产品方确认。

### 11.3 匿名机制（TBD，但若实现必须满足）

- 文案准确说明“对箱主匿名”与“对平台完全不可识别”不是同一概念。
- 不默认显示/传输可识别身份；只有在用户明确知道并同意时才收集邮箱或昵称。
- 需要回复能力时，优先使用安全一次性查询链接或经同意的联系方式；不得把提问者邮箱公开给箱主。

## 12. 异常、空状态与边界情况

| 情况 | 产品表现 |
|---|---|
| 箱子 slug 不存在/已停用 | 友好 404，不泄露是否曾存在的私密信息 |
| 问题为空/过长/包含不支持内容 | 就地提示具体修复方式，保留已输入文本 |
| 重复提交 | 按幂等键/短时间去重，避免产生多条相同问题 |
| 提交频率过高 | 清晰提示稍后再试，不披露风控阈值 |
| AI 生成中 | 禁用重复提交，显示可取消/返回；超时后可重试 |
| AI 失败或被安全策略拦截 | 不丢失原问题，提示人工回复仍可用 |
| 收件箱为空 | 展示分享链接和如何获得第一条问题的引导 |
| 筛选无结果 | 提供清除筛选操作 |
| 网络中断 | 明确离线/失败状态与重试；避免误报成功 |
| 未授权 | 401 跳转登录；403 给出无权限说明且不泄露资源细节 |
